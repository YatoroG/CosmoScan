# CosmoScan

## Предметная область

Данный проект реализует информационную систему, которая помогает преподавателям проверять присланные контрольные работы от студентов. Основные функции системы:

1. хранение сданных работ студентов;
2. проведение базовой технической проверки работы в автоматическом режиме;
3. формирование и сохранение отчета по результатам проверки;
4. получение отчета по каждой работе.

## Архитектура проекта

Проект поделен на несколько модулей:

1. `file-storing-service`: хранение документов и данных студентов;
2. `file-analysis-service`: проверка документов и генерация отчетов;
3. `gateway`: сервис-посредник.

### file-storing-service

#### Описание

Выполняет следующие функции:

- прием присланных документов от пользователя;
- управление загруженными документами и списком студентов, которые их прислали;
- хранение информации о документах и студентах.

#### API-запросы

| Команда | Запрос                                 | Возврат                      | Примечание                                                                   |
|---------|----------------------------------------|------------------------------|------------------------------------------------------------------------------|
| GET     | `api/storage/documents/{documentId}`   | Один файл                    | Получение документа по ID                                                    |
| GET     | `api/storage/documents?studentId={id}` | Массив метаданных документов | Получение всех документов по ID студента                                     |
| GET     | `api/storage/students?name={name}`     | Массив студентов             | Получение всех документов по имени студента                                  |
| GET     | `api/storage/documents/{id}/raw`       | Binary stream                | Скачивание файла                                                             |
| GET     | `api/storage/documents`                | Массив всех документов       | Получение списка всех документов в базе                                      |
| GET     | `api/storage/students`                 | Массив всех студентов        | Получение списка всех студентов в базе                                       |
| POST    | `api/storage/documents`                | JSON метаданных              | Добавление документа (и автоматически добавление студента, если его еще нет) |
| POST    | `api/storage/students`                 | JSON метаданных              | Добавление студента (если его еще нет)                                       |
| PUT     | `api/storage/documents/{documentId}`   | Измененные данные документа  | Редактирование данных документа                                              |
| PUT     | `api/storage/students/{studentId}`     | Измененные данные студента   | Редактирование данных студента                                               |
| DELETE  | `api/storage/documents/{documentId}`   | -                            | Удаление документа                                                           |
| DELETE  | `api/storage/students/{studentId}`     | -                            | Удаление студента (каскадное удаление его документов)

### file-analysis-service

#### Описание

Выполняет следующие функции:

- автоматическая проверка документа на соответствие формату (`.pdf`, `.txt`, `.docx`) и размеру (<= 1 Мб);
- генерация облака слов документа;
- формирование и хранение отчетов об анализе.

#### API-запросы

| Команда | Запрос                                        | Возврат                 | Примечание                                     |
|---------|-----------------------------------------------|-------------------------|------------------------------------------------|
| GET     | `api/analysis/overview`                       | Список отчетов          | Получение отчета со всеми документами          |
| GET     | `api/analysis/overview/{id}`                  | Отчет о документе       | Получение отчета по его id                     |
| GET     | `api/analysis/overview/{id}/cloud`            | Облако слов на картинке | Получение картинки с облаком слов              |
| GET     | `api/analysis/overview/{documentId}/document` | Отчет о документе       | Получение отчета о документе по его id         |
| POST    | `api/analysis/launch`                         | Отчет о документе       | Запуск анализа документа                       |

#### База данных

Используемая база данных: `analysis_db`. 

##### Таблица `reports`

| Атрибут       | Тип данных | Примечание                              | 
|---------------|------------|-----------------------------------------|

### gateway

#### Описание

Выполняет следующие функции:

- объединяет Swagger-документацию микросервисов;
- перенаправляет запросы между микросервисами по префиксам `/api/storage/**` и `/api/analysis/**`.

#### Доступ к API

- адрес: http://localhost:8080
- Swagger UI: http://localhost:8080/swagger-ui.html

## Сценарии микросервисов

### Пользовательские сценарии

В системе предусмотрены следующие пользовательские сценарии:

1. Загрузка и проверка: пользователь загружает документ, система возвращает ID и отправляет документ на проверку.
2. Просмотр результатов: пользователь запрашивает отчет по ID и видит, прошел ли документ проверку.
3. Визуализация облака слов: пользователь открывает сгенерированное облако слов для оценки содержания документа.

### Технические сценарии

В системе предусмотрены следующие технические сценарии:

1. Взаимодействие между сервисами: после сохранения документа `file-storing-service` отправляет запрос в `file-analysis-service` через `RestClient`.
2. Общее хранилище: сервисы взаимодействуют с документами через общую директорию (Docker Volume).
3. Обработка ошибок: при недоступности `file-analysis-service` процесс загрузки документа не прерывается, а ошибка появляется в логах.

## Визуализация облака слов

Для текстовых файлов (`.txt`) реализована генерация облака слов через внешний сервис `https://quickchart.io/wordcloud`. 

Результат сохраняется в базу данных `analysis_db` в формате `BYTEA` и выдается в виде PNG-изображения по запросу `api/analysis/overview/{id}/cloud`.
